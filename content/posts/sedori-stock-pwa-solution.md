# 動かない在庫アプリを直した手順：ファイル分離と、AIに任せない配置（解決編）

Nov 27, 2026 · @K

問題編では、せどり在庫アプリが動かなかった原因が、欠けた `app.js`・足りないアイコン・上書きされた `sw.js` だったことを書きました。解決編では、原因の突き止め方、直した内容、反映までの手順をまとめます。

---

## 1. 突き止め方：リポジトリを取得して、3つ確認する

公開ページの見た目だけでは、原因はわかりません。リポジトリを手元に取得して、次を確認しました。

1. **行数とサイズを比べる**：`wc -l` で、最初に作ったものと GitHub 上のものを比較（644行 vs 377行）
2. **構文チェック**：`node --check app.js` で、エラーの行を特定する
3. **履歴を見る**：`git log` で、`sw.js` の元の内容と、いつ上書きされたかを確認する

履歴が浅いと元のファイルが見えないので、`git fetch --depth=30` で少し深く取得しました。

---

## 2. 直した内容

### 在庫アプリのファイルを `stock.*` に分ける

他のアプリと名前がぶつからないよう、在庫アプリ専用の名前にしました。

| 役割 | ファイル名 |
| --- | --- |
| 画面 | `stock.html` |
| 本体 | `stock.js`（644行の完全版） |
| Service Worker | `stock-sw.js` |
| マニフェスト | `stock.webmanifest` |
| アイコン | `stock-icon-180.png` / `-192.png` / `-512.png` |

### 共通の `sw.js` を元に戻す

履歴から、lab-notes 用の元の内容を取り出して復元しました。これで `index.html` と `split-bill.html` は元どおりに動きます。

### Service Worker の範囲を絞る

在庫アプリの Service Worker は、`stock.html` だけを担当するように登録しました。

```js
navigator.serviceWorker.register('stock-sw.js', { scope: './stock.html' });
```

同じ範囲に Service Worker は1つしか置けません。範囲を絞ることで、ルート全体を担当する既存の `sw.js` とぶつからなくなります。

### アイコンを追加する

3サイズの PNG を作ってリポジトリに追加しました。キャッシュ対象のファイルが全部そろうので、Service Worker の登録も成功します。

---

## 3. 配置前に、手元でテストした

GitHub に上げる前に、手元で本物のブラウザ（Chromium ＋ 疑似カメラ）を動かして確認しました。

- JAN の手入力による入庫・出庫と、商品の新規登録
- 不正な JAN（チェックデジット違い）の拒否
- 在庫一覧・倉庫の追加
- Service Worker の有効化と、オフラインでの再読み込み（データが残る）

テスト環境ではネットワークが使えず、iPhone 用の ZXing の読み込みだけは確認できませんでした。カメラの読み取りは、実機で確かめる必要がありました。

---

## 4. 反映：AI に任せず、そのまま置く

### まず、iPhoneからファイルを保存

直したファイルを受け取り、リポジトリの `content/sources/` に保存しました。ここまでは iPhone の Safari だけでできます。ただ、ここに置いただけでは、公開ページには反映されません（直下に置く必要があります）。

### 次に、Issue で配置させたが、失敗

「直下へコピーして。中身は編集しない。`cmp` で一致を確認」と書いた Issue を出しました。しかし OpenHands は `git mv` で改名して中身を書き換えたため、判定は「解決できなかった」でした。コピーするだけの作業でも、AI は書き換えてしまうことがあります。

### 最後に、直接 push した

GitHub アカウントを Claude に連携して書き込み権限を渡し、次の手順で反映しました。

1. `content/sources/` から直下へ `cp` でコピー
2. 8ファイルすべてを `cmp` で照合（完全一致を確認）
3. `node --check` で `stock.js` / `stock-sw.js` / `sw.js` の構文を確認
4. 壊れた `app.js` と使わない `manifest.webmanifest` を削除
5. README のファイル名を更新して、main に push

1〜2分後に公開ページを開くと、カメラが起動しました。

---

## 5. うまくいくコツ

- **ファイルの配置は、AI に再生成させない**：コピーと照合だけを機械的に行う。長いファイルほど、書き直しで欠けやすい
- **サイズと行数を見る**：元と同じか、`node --check` が通るか。見た目では欠けに気づけない
- **共通ファイル名を使い回さない**：アプリごとに `stock-sw.js` のような専用名にして、Service Worker の範囲も絞る
- **キャッシュ対象は全部そろえる**：1つでも欠けると、Service Worker の登録が丸ごと失敗する
- **古い状態が残ったら**：Safari のタブを閉じて開き直す。ホーム画面に追加済みなら、アイコンを削除して追加し直す
- **カメラは実機で確認する**：作業環境のテストでは、実際の読み取りまでは確かめられない

---

## まとめ

- 動かない原因は、AI の取り込みで欠けた `app.js`、足りないアイコン、上書きされた共通の `sw.js` の3つ
- 直し方は、専用名への分離、`sw.js` の復元、Service Worker の範囲の限定、アイコンの追加
- 配置は、AI の再生成ではなく、コピー・照合・構文チェックで確実に行う
