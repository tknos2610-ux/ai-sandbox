# JANから商品名を自動で取りたい：せどり在庫アプリv3で詰まったこと（問題編）

Nov 27, 2026 · @K

せどり用の在庫管理アプリ（PWA）は、v2でJANコードのスキャンによる入出庫まで作りました。v3では「JANを読んだら商品名が自動で入る」機能を追加したかったのですが、思った以上に壁が多くありました。この記事では、つまずいた点を順番にまとめます。解決策は解決編にまとめています。

---

## 前提：やりたかったこと

- スマホのカメラでJANコードを読む
- 商品名が自動で入力欄に入る
- GitHub Pagesに置いた静的なアプリ（サーバーなし）から動かす
- できれば **APIキー不要・登録なし・無料** で

---

## 壁1：登録不要のAPIは日本の商品がほぼ当たらない

キーも登録もいらない商品データベースはあります。ただ、せどりで扱う商品にはほとんど対応していません。

| サービス | 登録 | 問題点 |
| --- | --- | --- |
| Open Food Facts | 不要 | 食品・飲料だけ。日本の商品は登録が少ない |
| UPCitemdb（お試し枠） | 不要 | 1日100回程度まで。海外商品が中心で日本のJANはあまり当たらない |

本・おもちゃ・家電・日用品はほぼ空振りする、という結論でした。

---

## 壁2：買取比較サイトからは取れない（取ってはいけない）

kaitorix.app（買取X）などの買取比較サイトはJANで検索できるので、ここから取れないか考えました。

- **買取X** には正式な Open API があり、JANを渡すと商品名と買取価格が返ってきます。ただし Googleログインが必要で、無料枠は1日30回、個人利用に限られます。「登録なし」の条件は満たせません
- 買取Xはサイトのデザイン・文章・データの無断転用を禁止すると明記しています。ページを勝手に読み取る（スクレイピング）のはNGです
- そもそも GitHub Pages のアプリから他サイトのページを直接読むと、ブラウザの仕組み（CORS）で基本的にブロックされます
- kaitori-search.app と kaitori.app は、APIがあるかどうか確認できませんでした

---

## 壁3：Jina Reader / defuddle.md を挟んでも解決しない

アカウントもキーもいらない「URLを渡すとMarkdownで返す」サービスとして、Jina Reader（r.jina.ai）と defuddle.md を検討しました。技術的には使えますが、今回の目的には合いませんでした。

- **本文抽出のためのツール**：記事やブログを読みやすくするもので、商品ページのような構造化データの抽出は苦手
- **JavaScriptで描画されるページに弱い**：価格をあとから読み込むページは中身が空で返ってくる可能性がある
- **規約は変わらない**：間に別サービスを挟んでも、元サイトがデータ転用を禁じていればNGのまま
- **不安定**：Jina Readerのキーなし枠は1分20回ほどで、同じIPの利用者全員で共有。仕様変更や停止があるとアプリの機能が止まる

---

## 壁4：大手のAPIも2026年に仕様が変わっていた

登録ありの公式APIも調べましたが、ここにも落とし穴がありました。

- **楽天ウェブサービス**：2026年に仕様が大きく変わり、旧API（app.rakuten.co.jp 系）は5月13日に廃止。新APIでは applicationId に加えて accessKey が必要になり、Referer のチェックも必須になりました。古い記事のやり方では403エラーで動きません
- **Amazon**：Product Advertising API 5.0 は廃止され、Creators API に移行。使うには承認済みのアソシエイトアカウントが必要で、自分用の在庫アプリのためだけに使うには敷居が高い

---

## まとめ：「登録なし・無料・確実」は同時に満たせない

- 登録不要のAPIは、日本の商品のヒット率が低い
- 買取比較サイトは、正式APIならログインが必要。スクレイピングは規約違反
- Markdown変換サービスを挟んでも、精度・規約・安定性の問題は消えない
- 大手の公式APIは登録が必要で、2026年に仕様も変わっている

1つのサービスで全部を解決するのは無理、とわかったので、複数の方法を組み合わせる方針に切り替えました。続きは解決編で書きます。
