# GitHub Actionsで毎日Pythonを自動実行したい：調べてわかった注意点（問題編）

Nov 27, 2026 · @K

GitHubに置いたPythonコードを、毎日決まった時間に自動で動かしたいと思いました。サーバーを借りずに、ネットから情報を取ってきてGitHubに保存するところまでできれば理想です。GitHub Actionsでできそうだとわかったものの、調べてみると気をつける点がいくつもありました。この記事では、その注意点をまとめます。実際の設定は解決編にまとめています。

---

## 前提：やりたかったこと

- GitHubのリポジトリに置いたPythonコードを動かす
- 毎日決まった時間に、自動で実行する
- ネットから情報を取ってきて、結果をGitHubに保存する
- サーバーは用意せず、できれば **無料** で

---

## 注意点1：時刻はUTCで指定する

GitHub Actionsでは、`schedule` に cron 形式で時刻を書きます。ただし時刻は **UTC（協定世界時）** です。

日本時間はUTCより9時間進んでいるので、日本時間から9時間引いた時刻を書く必要があります。たとえば日本時間の朝9時に動かしたいなら、UTCの0時（`0 0 * * *`）と書きます。そのまま「9時」と書くと、日本時間の18時に動いてしまいます。

---

## 注意点2：時間ぴったりには動かない

スケジュール実行は、指定した時刻ちょうどに始まるとは限りません。

- 数分〜数十分遅れることがある
- GitHub側が混雑していると、その回が飛ばされることもある

「毎日だいたいこの時間に1回動けばいい」という用途向けです。秒単位・分単位の正確さが必要な処理には向いていません。

---

## 注意点3：動くのはデフォルトブランチだけ

スケジュール実行の対象は、**デフォルトブランチ（通常は `main`）** に置いたワークフローとコードだけです。別のブランチで設定を書いても、スケジュールでは動きません。

---

## 注意点4：公開リポジトリは60日放置で止まる

公開リポジトリでは、**60日間リポジトリに更新がないと、スケジュール実行が自動で停止**されます。作って放置していると、いつのまにか動いていなかった、ということになりかねません。

---

## 注意点5：非公開リポジトリには無料枠の上限がある

公開リポジトリで標準のランナーを使う場合、GitHub Actionsは無料です。一方、非公開リポジトリには月ごとの無料枠があります。

| プラン | 実行時間（月） | ストレージ |
| --- | --- | --- |
| GitHub Free | 2,000分 | 500MB |
| GitHub Pro | 3,000分 | 1GB |

- 無料分は毎月初めにリセットされる
- 失敗した実行も、動いた時間の分だけ消費される
- Windows や macOS のランナーは、Linux より早く無料分を使ってしまう

---

## 注意点6：APIキーをコードに書いてはいけない

ネットから情報を取るときに、APIキーが必要なサービスもあります。キーをPythonコードにそのまま書くと、リポジトリを見た人に知られてしまいます（公開リポジトリならなおさらです）。

---

## 注意点7：結果を保存するには「書き込み権限」が要る

取ってきた情報をGitHubに保存するには、ワークフローの中でファイルをcommitしてpushします。ところが、ワークフローに書き込み権限を与えていないと、**pushの段階で失敗**します。

また、毎日実行していると、取ってきた内容が前日と同じ日もあります。そのまま `git commit` すると「変更がない」というエラーで止まってしまいます。

---

## 注意点8：取得先のサイトにも配慮が必要

ネットから情報を取る処理は、相手のサイトに負担をかけます。

- サイトの利用規約で、自動取得（スクレイピング）が禁止されていないか確認する
- アクセスの頻度を必要最小限にする
- X（旧Twitter）のように、APIを使わない自動取得がブロックされやすいサービスもある

---

## まとめ：できるけれど、押さえるポイントが多い

- 時刻はUTCで書き、日本時間から9時間引く
- 実行は数分〜数十分遅れることがあり、飛ばされることもある
- 動くのはデフォルトブランチだけ
- 公開リポジトリは60日放置でスケジュールが止まる
- 非公開リポジトリは月2,000分（Freeプラン）まで
- APIキーはコードに書かない
- 保存には書き込み権限と「変更なし」対策が必要

これらを踏まえた実際の設定は、解決編で書きます。
