# せどり在庫アプリをGitHub Pagesに置いたら動かなかった：原因は「壊れたapp.js」だった（問題編）

Nov 27, 2026 · @K

せどり用の在庫管理アプリ（PWA）の v1 を AI に作ってもらい、GitHub Pages に置いたところ「うまく動きません」。画面は出るのに何も反応しない状態でした。この記事では、何が起きていたのかを順番にまとめます。直し方は解決編に書きます。

---

## 前提：作ったもの

- スマホで JAN コードをカメラで読み、複数の倉庫に入庫・出庫を記録する
- GitHub Pages で公開し、Android はインストール、iPhone は「ホーム画面に追加」で使う。一度開けばオフラインでも動く
- 構成は PWA ＋ ブラウザ内の IndexedDB。iPhone の Safari は標準のバーコード読み取り（BarcodeDetector）に対応していないので、ZXing を使う
- 作業はスマホだけ・無料枠の範囲

AI が作った v1 は、入出庫・在庫一覧・倉庫管理・バックアップ・オフライン対応までを備えた、素の HTML/JavaScript の数ファイルです。

---

## 症状：ページは開くのに、何も動かない

公開した `stock.html` を開くと画面の枠は出ますが、ボタンを押しても何も起きません。ここから、リポジトリの中身を調べました。

---

## 原因1：GitHub 上の app.js が途中で欠けていた

いちばん大きな原因です。リポジトリの `app.js` を、AI が最初に作ったものと比べました。

| | 行数 | 構文チェック |
| --- | --- | --- |
| 最初に作ったもの | 644行 | OK |
| GitHub 上のもの | 377行 | `SyntaxError: missing ) after argument list` |

312行目あたりで、カメラの読み取り処理の途中から、いきなりタブ切り替えの処理に飛んでいました。間の約270行（カメラ、在庫一覧、倉庫、設定の画面）がごっそり抜けています。JavaScript は1か所でも構文エラーがあるとファイル全体が実行されないので、画面だけ出て何も動かなかったのです。

履歴を見ると、このファイルは「Issue から AI（OpenHands）に在庫アプリを取り込ませた」コミットで入っていました。AI がファイルをコピーせず、読んで書き直したために、途中で欠けたとみられます。

---

## 原因2：アイコン画像がリポジトリになかった

マニフェストと Service Worker が参照する `icon-180.png` / `icon-192.png` / `icon-512.png` が、リポジトリのどこにもありませんでした（あったのは別アプリ用の 1×1 ピクセルの `icon.png` だけ）。

Service Worker は、起動時に必要なファイルをまとめてキャッシュします。1つでも404になると、その登録は丸ごと失敗します。つまり、オフライン動作もホーム画面への追加も成立しません。

---

## 原因3：sw.js が上書きされて、ほかのアプリまで巻き込まれていた

このリポジトリには、別のミニアプリ（`index.html` と `split-bill.html`）が同居していて、どちらも `./sw.js` を登録しています。在庫アプリの取り込みで、この共通の `sw.js` が在庫アプリ用の内容に置き換わっていました。

- 元の `sw.js`：lab-notes 用で、`index.html` / `split-bill.html` をキャッシュする
- 上書き後：在庫アプリ用で、存在しない `app.js` やアイコンまでキャッシュしようとする

結果として、直接関係のない既存アプリのオフライン動作まで壊れていました。

---

## 追加で詰まったこと

- **AI から公開ページを読めない**：作業環境からは公開 URL を取得できず、リポジトリも最初は読めませんでした。中身の確認は、リポジトリを取得してからでないとできません
- **書き込み権限がない**：直したファイルを AI が直接 push しようとしても、GitHub アカウントを連携するまで 403 で拒否されました
- **iPhone だけだとファイルの差し替えが面倒**：zip は GitHub にそのままアップロードしても展開されないので、1つずつ上げる必要があります
- **Issue 経由の修正も失敗した**：「ファイルをコピーして配置して」という Issue を出しましたが、OpenHands は `cp` ではなく `git mv` で改名して中身を書き換え、「指示違反（解決できなかった）」と判定されました。試したブランチも、あとから確認すると見つかりませんでした

---

## まとめ：何が悪かったのか

- 「コピーするだけ」の作業を、AI が読んで書き直すと、長いファイルは途中で欠けることがある
- 欠けても画面だけは出るので、見た目では気づけない
- 共通のファイル名（`sw.js` など）を複数のアプリで使うと、上書き事故が起きる
- Service Worker は、キャッシュ対象が1つでも欠けると丸ごと失敗する

次の解決編で、原因の突き止め方と、実際に直した手順を書きます。
